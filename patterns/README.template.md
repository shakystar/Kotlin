## 해결하려는 문제

어떤 상황에서 무엇을 변경하거나 확장하기 어려운가?

## 패턴 없이 구현하면

직접 구현했을 때 생기는 중복, 결합, 변경 부담을 구체적인 시나리오로 설명한다.

## 이 예제의 해결 방식

실제 파일의 상대 링크, 각 객체의 책임, 호출 흐름을 작성한다.

## 실행과 확인

Main.kt 실행 방법과 현재 코드의 예상 출력을 작성한다. 출력에서 확인할 핵심과 추가로 코드를 바꿔볼 실험을 구분한다.

## 장점과 비용

어떤 변경이 쉬워지는지, 대신 클래스 수·상태·추적 비용 등이 얼마나 늘어나는지 작성한다.

## 적용할 때와 쓰지 않아도 될 때

적합한 조건, 더 단순한 대안, 비슷한 패턴과의 차이, 예제에서 구현하지 않은 범위를 작성한다.
