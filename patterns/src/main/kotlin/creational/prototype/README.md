# 프로토타입 (Prototype)

[전체 학습 안내](../../../../../README.md)

## 해결하려는 문제

기존 객체의 설정을 바탕으로 일부만 바꾼 새 객체가 필요할 때, 생성 인자를 다시 나열하지 않고 복제하고 싶다.

## 패턴 없이 구현하면

원본의 모든 프로퍼티를 읽어 생성자에 다시 전달하면 반복이 생기고 새 프로퍼티를 빠뜨릴 수 있다. 한편 단순히 다른 변수에 원본을 대입하면 복제가 아니라 같은 객체의 참조를 공유한다.

## 이 예제의 해결 방식

| 파일 | 역할 |
|---|---|
| [Character.kt](Character.kt) | `data class`로 이름, 레벨, 체력, 아이템을 담는다. |
| [Main.kt](Main.kt) | `copy()`로 캐릭터를 복제하고 `toMutableList()`로 아이템 리스트도 분리한다. |

`original → copy(name, items = original.items.toMutableList()) → copied.items.add()`

## 실행과 확인

[Main.kt](Main.kt)를 저장한 뒤 VS Code에서 열고 `⌘ + Shift + B`로 실행한다. 환경 준비는 [전체 학습 안내](../../../../../README.md)를 참고한다.

현재 코드의 출력:

```text
[검]
[검, 방패]
false
false
```

원본에는 검만 남고 복사본에는 방패가 추가된다. 캐릭터와 리스트에 대한 `===` 비교가 모두 false다. 추가 실험으로 `items = ...` 인자를 생략하면 리스트는 공유되어 원본에도 방패가 추가되고 마지막 비교는 true가 된다.

## 장점과 비용

기존 값을 재사용해 변형을 만들기 쉽다. 대신 복사의 깊이를 결정해야 한다. `copy()`는 얕은 복사이고 `toMutableList()`도 요소 객체까지 복제하지 않는다. 현재 요소는 불변 문자열이라 리스트를 분리하면 충분하다. 변경 가능한 Item 객체라면 각 요소도 복제해야 한다.

## 적용할 때와 쓰지 않아도 될 때

기본 설정이나 템플릿을 복제해 변형을 만들 때 적합하다. 객체 생성이 간단하거나 원본 값 재사용이 필요 없으면 생성자로 충분하다. 이 예제는 Kotlin의 `copy()`로 복제 개념을 익히는 것으로, 다형적 복제 인터페이스나 프로토타입 등록소는 구현하지 않았다.
