# 추상 팩토리 (Abstract Factory)

[전체 학습 안내](../../../../../../README.md)

## 해결하려는 문제

버튼과 체크박스처럼 관련된 객체들을 제품군별로 생성하면서, 사용하는 코드가 구체 테마 클래스에 의존하지 않게 해야 한다.

## 패턴 없이 구현하면

화면이 버튼과 체크박스를 각각 직접 생성하면 테마 선택 로직이 화면에 들어간다. 여러 곳에서 선택하면 밝은 버튼과 어두운 체크박스를 실수로 섞을 수도 있다.

## 이 예제의 해결 방식

| 파일 | 역할 |
|---|---|
| [product/Button.kt](product/Button.kt) | 버튼의 공통 규칙. |
| [product/Checkbox.kt](product/Checkbox.kt) | 체크박스의 공통 규칙. |
| [ThemeFactory.kt](ThemeFactory.kt) | 두 종류의 제품을 생성하는 공통 규칙. |
| [light/LightThemeFactory.kt](light/LightThemeFactory.kt) | 밝은 테마 제품들을 생성한다. |
| [dark/DarkThemeFactory.kt](dark/DarkThemeFactory.kt) | 어두운 테마 제품들을 생성한다. |
| [Screen.kt](Screen.kt) | 팩토리를 받아 제품을 만들고 공통 인터페이스로 사용한다. |
| [Main.kt](Main.kt) | 두 팩토리를 각각 연결해 화면을 실행한다. |

`ThemeFactory 선택 → Screen 생성 → 버튼·체크박스 생성 → render()`

## 실행과 확인

[Main.kt](Main.kt)를 저장한 뒤 VS Code에서 열고 `⌘ + Shift + B`로 실행한다. 환경 준비는 [전체 학습 안내](../../../../../../README.md)를 참고한다.

현재 코드의 출력:

```text
밝은 테마 버튼
밝은 테마 체크박스
어두운 테마 버튼
어두운 테마 체크박스
```

밝은 테마 두 줄, 어두운 테마 두 줄이 출력된다. `Screen`은 동일하고 전달한 팩토리에 따라 제품군이 달라진다. 실제 GUI 대신 콘솔 출력으로 표현한다.

## 장점과 비용

제품군 교체를 생성 단계에서 모을 수 있다. 새 테마 추가는 구현체와 팩토리 추가로 가능하지만, 슬라이더처럼 새 제품 종류를 추가하면 인터페이스와 모든 팩토리를 수정해야 한다. 테마 일치는 각 팩토리가 올바른 제품을 반환한다는 구현에 달려 있으며 타입만으로 강제되지는 않는다.

## 적용할 때와 쓰지 않아도 될 때

서로 관련된 여러 종류의 객체를 제품군 단위로 바꿀 때 적합하다. 생성할 제품이 하나뿐이거나 제품군 교체가 필요 없다면 더 단순한 팩토리나 직접 생성으로 충분하다.
