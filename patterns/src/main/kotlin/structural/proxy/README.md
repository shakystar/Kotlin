# 프록시 (Proxy)

[전체 학습 안내](../../../../../README.md)

## 해결하려는 문제

호출자가 실제 문서에 바로 접근하면 조회 권한을 일관되게 검사하기 어렵다. 실제 객체를 대신하는 접근 지점에서 허용 여부를 판단하고 싶다.

## 패턴 없이 구현하면

각 호출부가 권한을 직접 확인하면 검사가 중복되거나 누락될 수 있다. 문서 클래스에 검사를 모두 넣을 수도 있지만, 이 예제는 조회와 접근 제어의 책임을 분리한다.

## 이 예제의 해결 방식

| 파일 | 역할 |
|---|---|
| [document/Document.kt](document/Document.kt) | 실제 문서와 프록시가 공유하는 `read(): String` 규칙. |
| [document/SecretDocument.kt](document/SecretDocument.kt) | 문서 내용을 보관하고 조회 로그와 함께 반환한다. |
| [protection/DocumentProxy.kt](protection/DocumentProxy.kt) | 읽기 권한을 검사하고 허용된 경우에만 실제 문서를 호출한다. |
| [Main.kt](Main.kt) | 허용·거부를 비교하고 SecurityException을 출력으로 처리한다. |

`read() → 권한 검사 → 허용: document.read() / 거부: SecurityException`

## 실행과 확인

[Main.kt](Main.kt)를 저장한 뒤 VS Code에서 열고 `⌘ + Shift + B`로 실행한다. 환경 준비는 [전체 학습 안내](../../../../../README.md)를 참고한다.

현재 코드의 출력:

```text
=== 권한 있음 ===
[실제 문서] 내용을 조회합니다.
다음 분기 출시 계획

=== 권한 없음 ===
접근 거부 : 문서를 읽을 권한이 없습니다.
```

허용된 요청에서만 [실제 문서] 로그와 문서 내용이 나온다. 거부된 요청은 접근 거부 메시지만 출력하며 실제 문서의 read는 호출되지 않는다.

## 장점과 비용

문서 조회와 권한 판단을 분리한다. 대신 프록시를 통하지 않는 접근 경로가 있으면 검사를 우회할 수 있다. 현재 Main은 원본도 보유하므로 이 코드는 완전한 보안 경계가 아니다. 실제 백엔드에서는 서버가 확인한 사용자 정보로 권한을 판단하고 보호 대상에 이르는 경로를 통제해야 한다.

## 적용할 때와 쓰지 않아도 될 때

실제 객체에 대한 접근을 대신 관리할 때 적합하다. 여기서는 보호 프록시를 구현했다. 지연 생성·원격 호출·캐싱도 다른 활용 형태지만 현재 예제에는 없다. 별도의 접근 관리가 필요 없다면 직접 호출하면 된다. 데코레이터와의 구분은 원본 호출 여부만이 아니라 설계 목적에 있다.
