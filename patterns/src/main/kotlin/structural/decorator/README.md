# 데코레이터 (Decorator)

[전체 학습 안내](../../../../../README.md)

## 해결하려는 문제

로그와 접두사 같은 선택 기능을 조합할 때마다 기존 클래스를 수정하거나 모든 조합에 해당하는 하위 클래스를 만들고 싶지 않다.

## 패턴 없이 구현하면

기본 알림 클래스에 모든 옵션을 넣으면 조건문이 늘어난다. 상속만으로 조합하면 로그 알림, 접두사 알림, 로그와 접두사 알림처럼 조합별 클래스가 늘어난다.

## 이 예제의 해결 방식

| 파일 | 역할 |
|---|---|
| [notification/Notifier.kt](notification/Notifier.kt) | 기본 객체와 데코레이터가 함께 구현하는 인터페이스. |
| [notification/ConsoleNotifier.kt](notification/ConsoleNotifier.kt) | 기본 알림 출력. |
| [decorators/LoggingNotifier.kt](decorators/LoggingNotifier.kt) | 전송 전후에 로그를 추가한다. |
| [decorators/PrefixNotifier.kt](decorators/PrefixNotifier.kt) | 메시지 앞에 접두사를 붙여 내부 객체에 전달한다. |
| [Main.kt](Main.kt) | 기본, 로그 추가, 로그와 접두사 조합을 비교한다. |

`LoggingNotifier → PrefixNotifier → ConsoleNotifier`

## 실행과 확인

[Main.kt](Main.kt)를 저장한 뒤 VS Code에서 열고 `⌘ + Shift + B`로 실행한다. 환경 준비는 [전체 학습 안내](../../../../../README.md)를 참고한다.

현재 코드의 출력:

```text
=== 기본 알림 ===
알림 전송: 가입을 환영합니다.

=== 로그를 추가한 알림 ===
[로그] 알림 전송 시작
알림 전송: 가입을 환영합니다.
[로그] 알림 전송 완료

=== 로그 + 접두사 알림 ===
[로그] 알림 전송 시작
알림 전송: [주문] 결제가 완료되었습니다.
[로그] 알림 전송 완료
```

기본 출력에는 로그가 없고, 조합한 출력에는 시작·완료 로그와 [주문] 접두사가 함께 나온다. 데코레이터 자신도 Notifier이므로 다른 데코레이터가 감쌀 수 있다.

## 장점과 비용

원본 클래스를 수정하지 않고 기능을 선택해 조합한다. 대신 감싸는 단계가 많으면 실행 흐름을 추적하기 어려워진다. 순서가 결과에 영향을 줄 수 있다. 현재 로그는 메시지를 출력하지 않아 두 데코레이터의 순서를 바꿔도 같은 출력이지만, 메시지를 기록하면 접두사 적용 전후가 달라진다. 내부 전송이 예외를 던지면 완료 로그는 실행되지 않는다.

## 적용할 때와 쓰지 않아도 될 때

선택 기능을 독립적으로 조합할 때 적합하다. 항상 필요한 단일 동작이라면 일반 함수나 기존 클래스에 두는 것이 더 단순할 수 있다. 프록시와 구조가 비슷하지만 여기서의 목적은 접근 통제보다 기능 확장이다.
